# 双语文章：一次生成英中句对

2026-10-06：按用户要求发布重构版本，供线上试用。本轮模型测试只使用当前对话配置的 `gpt-6.1-sol / high`，通过 Codex 登录调用；未调用 Texta 的 API、读取其 API key 或向其 DeepSeek 服务发送测试请求。网页检查使用本地模拟服务，实际 DeepSeek 生成表现待线上试用验证。

## 当前流程

1. 校验、去重输入词汇，最多120个，预留1积分。
2. 一次模型请求生成英文标题和逐段英中句对。英文目标词带编号，中文对应位置同时包含编号、词性、该处译义。事件设计在生成请求内完成，不单独输出或请求故事计划、完整词典、翻译稿、对齐表。
3. 代码校验合法JSON、英中语言、原词边界、词性、全部词汇、每个句对的编号及次数、正文长度。孤立量词不能充当名词释义；重复标记最多两次。标记不完整时不猜补或追加凑词句。
4. 校验失败最多重新生成一次；模型传输失败直接返回错误，不叠加自动网络重试。最终失败退回积分。
5. 去掉标记，直接构造段落、语境词义、每个词的精确高亮位置和英中句对。
6. 生成完成不预取完整词典。点击单词按需获取词典详情；该详情不会覆盖文章使用的义项。例句中文复用已保存句对，不额外调用翻译模型。
7. 句对及高亮位置随收藏、历史记录和生词来源保存；云端继续使用现有 alignment JSON 元数据，无数据库迁移。旧文章没有句对和位置数据时继续使用原有阅读兼容逻辑。

## 篇幅

输入词数为n。普通双语英文目标下限 `max(100,60+7n)`，上限 `max(160,100+10n)`；短文模式下限 `max(60,35+5n)`，上限 `max(100,65+7n)`。它们是目标范围，校验使用0.6倍下限和1.25倍上限，给自然表达留出余量。

| 输入词数 | 普通双语英文目标 | 短文模式英文目标 |
|---|---|---|
| 6 | 102–160词 | 65–107词 |
| 12 | 144–220词 | 95–149词 |
| 24 | 228–340词 | 155–233词 |

允许有理解事件所需的背景、动机、转折和结果；不要求每句都塞入目标词。随机词表可以沿同一人物的具体任务推进，避免虚构科学因果。输入词越多，篇幅和输出预算越大，避免旧固定420-token短文预算导致截断。

## Prompt与数据结构

唯一应用生成prompt是 `generation/bilingual.cjs` 的 `buildBilingualPrompt`。本轮实测的应用prompt、模型原始输出和报告保存在本地 `experiments/bilingual-2026-10-06/`，实验运行日志不随生产版本上传。

```json
{"title":"A Repair Plan","paragraphs":[[["The ⟦1|budget⟧ was small.","⟦1|n.|预算⟧很少。"],["We changed the ⟦2|process⟧.","我们调整了⟦2|n.|流程⟧。"]]]}
```

以上仅示意结构，不是符合正式篇幅要求的完整故事。模型不生成词典的全部义项、搭配、词根、近反义词，也不重复输出用于对齐的英文形式和中文词表。

## 选项与兼容

- 初级/中级/高级选择及生成请求中的level已移除，后台忽略旧客户端的level。
- 快速模式更名为短文模式，前端使用shortMode；后台兼容旧quickMode，shortMode显式值优先。旧草稿quick字段迁移到short，旧高级生成档位归为普通。
- 中英混合的方向不变，仅移除难度标签；双语文章不使用已删除的多步骤生成函数及其prompt。
- 线上模型配置仍是deepseek-v3.2，统一1积分。Codex测试模型不写入网站配置。

## 验证范围

生成、词汇详情语境、英中精确高亮、收藏云端往返、计费和失败退款已通过本地回归检查。模型语义需要人工阅读；程序只能检查覆盖、结构和部分明显问题，不能证明所有词义、故事因果和翻译永远正确。Codex样例不能代替真实DeepSeek运行的质量、速度或token实测。本轮没有测量旧新DeepSeek的改善百分比。
