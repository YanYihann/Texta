# 生成时准备解析，点击直接展示

2026-10-06：中英混合和双语文章共用此流程，保留各自正文提示词与文章形式。通用解析提示词完整源码为 `generation/vocabulary.cjs` 中的 `buildVocabularyPrompt`。

1. 输入校验、去重与预留1积分后，同时开始正文生成及词典准备。
2. 按小写原词和归一化空格读取 `VocabularyDetail` 表中的完整卡片。缓存与用户、文章、生成模型无关，没有时间到期；仅格式版本变化或存储数据不合法时重建。
3. 缺失的词按每批最多12词生成，最多2批并行，同一服务器进程中重叠请求共享正在生成的词。提示词只要求通用中文常用义、真实英美音标、1–2个搭配、简短构词及适用的近反义词，不传入故事，也不生成额外例句。
4. 校验JSON、原词、词性及各字段，完整合法结果写入数据库后才标记 `detailsReady`。无可靠音标的短语可保留空值，无合适近反义词可保留空数组；这些不代表解析未完成。校验失败最多重生成一次，传输失败不自动重试，不缓存占位或失败结果。
5. 等待正文及解析均完成，一起返回 `baseLexicon`（通用词典）及 `lexicon`（保留本文词性、义项的完整卡片）。文章注释、主释义和例句优先使用本次语境，其余通用释义可以在卡片词义列表中查看。
6. 浏览器预先渲染卡片，点击只选中卡片，不再请求 `/api/vocab/detail`。解析随收藏、历史和生词本保存；云端生词本也保留英美音标、通用释义及完成标记。
7. 旧的不完整收藏或生词本在打开时批量准备，而非点击时逐个生成，使用 `/api/vocab/details`。已完成的新文章无需补取。旧内容准备失败保留原内容，可在后续打开时重试。

首次全部为新词时，多一次批量词典请求会增加token，并可能延长等待。理想情况下总等待接近两项工作中较慢的一项，另加校验和存储时间，而非把两项耗时相加。已有缓存的词只读数据库，后续换文章、刷新或服务重启不需要重新生成通用解析。新文章仍需单独生成语境义项，不能直接用通用词义替换。

生成最终失败退回预留积分，已经成功保存的通用词典卡仍可复用。多实例之间没有分布式生成锁，极少量同时首次提交的同词可能重复请求；数据库主键保证最后只保留一张卡。

部署通过现有 `prisma db push` 添加 `VocabularyDetail` 表和 `NotebookEntry` 的 `usIpa/ukIpa/baseMeanings/detailsReady` 字段，不删除旧数据。后端启动会检查缓存表是否存在，健康检查包含 `vocabularyVersion: 1`。

验证包括缓存跨实例/模型复用、并发词去重、失败不缓存、正文与词典并行并等待就绪、点击不取解析、收藏/生词本云端往返及生成失败退款。模型内容样例仅使用当前对话模型，页面检查使用本地模拟服务。本轮没有调用 Texta/DeepSeek 生成API，也没有测量实际DeepSeek首次及缓存命中的耗时；不据此宣称固定秒数或提升比例。
